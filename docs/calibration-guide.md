# ปรับ LabFlow ด้วยข้อมูลจริง

เป้าหมายคือทดสอบสมมติฐานคิวและกำลังรองรับ ไม่ใช่นำค่าตั้งต้นของแอปไปอ้างเป็นผลของโรงพยาบาล

## ข้อมูลที่ควรเก็บ

เก็บวันที่มีบริการปกติและวันที่งานมาก แยกวัน/ช่วงเวลา/ระดับความเร่งด่วน/ห้องตรวจ อย่างน้อยให้ครอบคลุมรอบงานที่ต้องการวิเคราะห์ ไม่ตั้งจำนวนวันขั้นต่ำโดยไม่มีข้อมูลความแปรปรวน

| ส่วนงาน | ข้อมูลสำหรับใส่ค่าระบบ | จุดเวลาที่ต้องมี |
|---|---|---|
| ขึ้นบัตร | จำนวนผู้ทำงานจริง, service time, อัตราเข้าแต่ละช่วง | มาถึง, เริ่ม/จบลงทะเบียน |
| เก็บตัวอย่าง | ช่องที่เปิดจริง, เวลาเก็บเลือด, ปัสสาวะ, สัดส่วนคำสั่งตรวจ | ยื่นบัตร, เริ่ม/จบเก็บ |
| กระสวย | station ต้นทาง/ปลายทาง, รอบส่ง, จำนวน carrier, ความจุที่ validation รองรับ, ชนิดตัวอย่างที่อนุญาต | เข้าคิว, ออกเที่ยว, ถึง, carrier พร้อมใช้ใหม่ |
| ส่งสำรอง | นโยบาย trigger, ทีม/รอบ/ความจุ/เวลาเดิน | ขอส่งสำรอง, ออก, ถึง, ทีมพร้อมออกใหม่ |
| จุดรับ | จำนวนเจ้าหน้าที่/ช่องจริง, เวลาและเกณฑ์ตรวจรับ, อัตราปฏิเสธและเหตุผล | ถึงจุดรับ, เริ่มตรวจ, รับเข้า/ปฏิเสธ |
| เตรียม | SOP serum, capacity/เวลา centrifuge, นโยบายรวม batch/STAT | พร้อมปั่น, เริ่ม/จบปั่น, พร้อมวิเคราะห์ |
| วิเคราะห์ | จำนวนช่องงานสมมูลและเวลา panel แยกห้อง, QC/downtime/rerun | เข้าคิว, เริ่ม/จบวิเคราะห์ |
| LIS | เวลาตรวจสอบ/อนุมัติ, จำนวนผู้มีสิทธิ์, วิธี autoverification จริง | บันทึก, verify, authorize |
| HIS | เวลา ACK/แสดงผล, error/retry และ duplicate handling | ส่งข้อความ, ACK, HIS บันทึก, แสดงผล |

เชื่อมด้วย pseudonymous patient ID + encounter ID + order ID + specimen ID (รวม parent aliquot/recollection) โดยไม่ใส่ชื่อจริง/HN/เลขบัตรประชาชนลงเว็บนี้ แอปนำเข้าเฉพาะไฟล์ตั้งค่า ไม่รับ patient log จริง

## วิธีใช้ในแอป

1. ส่งออกค่าระบบ JSON เพื่อใช้เป็นแม่แบบ ใส่ค่าที่วัดได้ โดยหน่วยเวลาเป็นวินาที จำนวนทรัพยากรและความจุเป็นจำนวนเต็ม
2. บันทึกแหล่งข้อมูลและช่วงวันที่ในช่องที่มา เก็บค่าจำลองไว้เมื่อยังไม่ทราบ อย่าเลือกป้ายข้อมูลจริงเพื่อแทนการตรวจสอบ
3. กระสวยรุ่นนี้รองรับ **ห้องเก็บตัวอย่าง → จุดรับสิ่งส่งตรวจหนึ่งเส้นทาง** ถ้าของจริงเป็นเครือข่ายหลายสถานี ควรเพิ่ม graph routing และ shared segment capacity ก่อนใช้เปรียบเทียบการขนส่งข้ามแผนก
4. ความจุในแอปนับภาชนะ ไม่ใช่มวล/ปริมาตร carrier กำหนดจำนวนสมมูลที่สอดคล้องกับ SOP จริง รุ่นถัดไปจึงค่อยเพิ่มข้อจำกัดหลายหน่วย
5. ตั้งสัดส่วน CBC/เคมี/UA/ภูมิคุ้มกันและ STAT ตาม workload จริง ค่า analysis เป็นเวลาต่อ panel ในแบบจำลองช่องขนาน ต้องปรับเทียบกับ throughput และ turnaround ของเครื่องจริง ไม่คัดลอก tests/hour เป็นช่องเครื่องโดยตรง
6. เริ่มรอบใหม่ ใช้ seed เดิม เดินเวลาช่วงเดียวกัน เทียบ queue profile, P50/P95, SLA และงานค้างกับข้อมูลจริง แยก warm-up 15 นาทีและช่วงที่จงใจใส่เหตุขัดข้อง
7. หากตัวเลขไม่ตรง ให้ปรับโครงสร้างหรือ distribution ก่อนสรุปว่าทรัพยากรไม่เพียงพอ ปัจจุบันเวลา service ส่วนใหญ่คงที่ อัตราเข้ามี jitter 0.65–1.35 เท่าของระยะห่างเฉลี่ย ยังไม่แทน arrival profile ที่เปลี่ยนรายชั่วโมง

## ตัวเลือกที่เป็นนโยบาย ไม่ใช่ข้อเท็จจริงสากล

- ปัสสาวะห้ามเข้ากระสวยในค่าตั้งต้น เป็นสมมติฐาน ต้องตัดสินจาก validation ของระบบของคุณ
- รอ serum 180 วินาที เป็นเพียงค่าจำลอง ไม่ใช่คำแนะนำเวลา clotting ทางคลินิก
- อนุมัติ/แจ้งค่าวิกฤตอัตโนมัติ เป็นโหมดฝึก ต้องแทนด้วยกฎจริงถ้าจะศึกษางาน autoverification
- QC ผ่าน/ไม่ผ่าน เป็น binary gate ไม่ใช่การคำนวณ Westgard หรือการตีความค่า QC จริง
- ค่าวิกฤตและตัวเลขผลตรวจสร้างเพื่อฝึก workflow ไม่ใช่ critical limits/interval ของโรงพยาบาล
- การขัดข้องเครื่องตรวจหยุดรับงานใหม่ งานเริ่มแล้วดำเนินต่อ หากระบบจริงทำให้ผลใช้ไม่ได้ต้องเพิ่มนโยบาย invalidation/rerun

อ้างอิงการตรวจรับ/ปฏิเสธ/ติดตาม aliquot: WHO LQMS และ Sample Processing; การตรวจสอบ/อนุมัติและ linkage: IHE LTW; SOP และ critical communication ต้องยึดของโรงพยาบาลจริงร่วมกับมาตรฐานวิชาชีพ รายละเอียดลิงก์ในบันทึกงานวิจัย
