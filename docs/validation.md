# Validation — v1.0

ตรวจสอบ 11 ตุลาคม 2026 บน Node.js 22.18.0 / Python 3.13.3 / Chromium headless (Playwright)

## Engine: 12 กรณีผ่าน

1. ตั้งแต่รับบริการจนผลครบ HIS พร้อมลำดับเวลาและรหัส aliquot
2. ผลรออนุมัติอยู่ภายใน LIS และไม่ส่งออกก่อนอนุมัติ
3. กระสวยจำกัดความจุ รอเที่ยว รอ carrier กลับ และเคารพเส้นทางที่อนุญาต
4. กระสวยหยุดแล้วงานใหม่รอเกณฑ์ส่งสำรอง งานที่อยู่ระหว่างเที่ยวไปถึงปลายทาง
5. QC ไม่ผ่านระหว่างอนุมัติ ยกเลิกงานเดิมและบังคับวิเคราะห์ใหม่ แม้แก้ QC อย่างรวดเร็ว
6. HIS ล่ม เก็บ outbox และ retry หลังฟื้นตัวตอบรับสำเร็จเพียงครั้งเดียว
7. ผลแก้ไขมีเวอร์ชันใหม่ เก็บฉบับเดิมใน HIS จนฉบับใหม่อนุมัติและถึง HIS
8. รหัสสิ่งส่งตรวจไม่ตรงถูกพักรับ เก็บใหม่ผ่านคิว/เวลาและเชื่อมรหัสเดิม
9. ค่าวิกฤตมีงานบันทึกผู้รับแจ้งและอ่านทวนแยกจากผล
10. Seed/ค่าตั้งเดียวกัน เดินทีละ 10 วินาทีหรือเดิน 2 ชั่วโมงรวดเดียวได้ snapshot เท่ากัน
11. การตั้งค่าปฏิเสธค่า NaN/ติดลบ/จำนวนช่องงานที่เป็นเศษ และไม่แก้ default โดยไม่ตั้งใจ
12. Load run ระยะ 3 ชั่วโมง ระยะห่างผู้รับบริการ 15 วินาที: จำนวนงานพร้อมกันไม่เกินทรัพยากร รหัสไม่ซ้ำ ส่งออก snapshot ได้

## Browser: 12 กลุ่มผ่าน

Desktop/WebGL/font local, หยุด/เดินเวลา, สามเส้นทางเชื่อมกัน, เพิ่ม STAT, กระสวยขัดข้อง/คืนระบบ, แก้ไขผล/อนุมัติ, CSV, Analytics, validation/persistence/JSON, คู่มือ/แหล่งอ้างอิง, mobile 390px, 2D fallback เมื่อปิด WebGL ไม่มี JavaScript page error ระหว่างทดสอบ

ตรวจภาพหน้าห้องแล็บ LIS ตัวชี้วัด ตั้งค่า และมือถือจริงจาก screenshot ใน `.qa/` รวมทั้งกรณีปิด WebGL

## สิ่งที่การทดสอบนี้ยังไม่ยืนยัน

- ไม่ใช่ validation เทียบข้อมูลโรงพยาบาลหรือผลการศึกษาเชิงคลินิก
- ไม่ยืนยัน throughput ของเครื่องตรวจ กระสวยหรือภาระงานจริง
- ไม่ได้เชื่อมและทดสอบข้อความ HL7/FHIR กับ HIS จริง รูปแบบ MSG/ACK ใน engine เป็นสัญลักษณ์จำลอง
- ไม่ได้ตรวจความถูกต้องของวิธีวิเคราะห์/QC/เกณฑ์ค่าวิกฤตจริง
- ไม่ได้ทำ formal accessibility audit ครอบคลุมทุก screen reader แต่มี semantic controls, labels, keyboard focus, dialog, reduced motion และ responsive checks

ใช้ `npm test` และ `python tests/browser_test.py` เพื่อทำซ้ำ โดย browser tests ต้องเปิด server ที่ 127.0.0.1:4173 ก่อน
